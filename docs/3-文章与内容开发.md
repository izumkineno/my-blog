# 文章与内容开发

## 创建文章

推荐使用本地 CMS 管理文章。分别启动 Astro 和 Sveltia CMS：

```bash
pnpm dev
pnpm cms
```

浏览器打开 CMS 终端输出的地址，默认是 `http://127.0.0.1:4325`。点击“Work with Local Repository”，按提示选择当前 Git 仓库根目录。CMS 会读取 `cms/config.yml`，提供文章列表、Frontmatter 表单、原始 Markdown 编辑和文章目录内的图片管理。

CMS 依赖 Chromium 的 File System Access API，推荐使用 Chrome 或 Edge。所有保存和删除操作都会直接修改工作区文件，但不会自动执行 Git commit 或 push；保存前后都应检查 Git diff。

也可以使用命令行创建草稿：

```bash
pnpm new-post my-first-post "我的第一篇文章"
```

脚本会创建 `src/content/posts/my-first-post/index.md`，写入标题、当天日期和 `draft: true`。`slug` 只能包含字母、数字和用于分隔单词的连字符；目标文章已存在时，脚本会终止并保留原文件。

## 文章目录

项目统一使用 page bundle，让文章和专属资源保持在同一目录：

```text
src/content/posts/
└── my-first-post/
    ├── cover.jpeg
    └── index.md
```

`index.md` 的 slug 来自其所在目录。封面和正文图片使用 `./cover.jpeg` 等相对路径，重命名、移动或删除文章时应连同整个目录一起处理。

## Frontmatter

`src/content/config.ts` 使用 Zod schema 校验 `posts` collection。最小可用示例：

```yaml
---
title: My First Blog Post
published: 2026-01-01
description: A short description for the post.
image: ./cover.jpg
tags: [Astro, Blogging]
category: Guides
draft: false
lang: en
---
```

字段约定：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | string | 必填，文章标题 |
| `published` | date | 必填，发布日期 |
| `updated` | date | 可选，最后更新时间 |
| `description` | string | 可选，默认空字符串；用于列表和页面描述 |
| `image` | string | 可选，文章封面；默认空字符串 |
| `tags` | string[] | 可选，默认空数组 |
| `category` | string 或 null | 可选，默认空字符串 |
| `draft` | boolean | 可选，默认 `false`；生产构建会排除 `true` |
| `lang` | string | 可选，文章语言；默认跟随站点语言 |

`prevTitle`、`prevSlug`、`nextTitle` 和 `nextSlug` 是运行时用于文章导航的内部字段，不需要手动填写。

## 图片路径

文章封面由 `src/components/misc/ImageWrapper.astro` 解析：

1. `./cover.jpg` 这类相对路径指向文章目录中的本地资源，由 Astro 处理。
2. `/images/cover.jpg` 这类以 `/` 开头的路径指向 `public/`，会结合站点 `base` 生成 URL。
3. `https://...` 或 `http://...` 使用远程图片 URL。
4. 文章内图片同样建议优先放在对应 page bundle 中，避免文章迁移后丢失资源。

## Markdown 扩展

项目在 `astro.config.mjs` 中启用了以下能力：

- GitHub Flavored Markdown 基础语法。
- 数学公式和 KaTeX。
- `note`、`tip`、`important`、`warning`、`caution` 提示块。
- `::github{repo="owner/name"}` GitHub repository card。
- Expressive Code 代码块，包括行号、语言标识、可折叠区段和复制按钮。
- 标题锚点和阅读时间、摘要处理。

示例文章已从仓库清理。需要验证 Markdown 扩展时，建议新建一篇临时草稿文章，按需加入数学公式、提示块、代码块、图片和嵌入内容，确认后再发布或删除。

## 草稿与预览

`src/utils/content-utils.ts` 根据 `import.meta.env.PROD` 过滤草稿：

- `pnpm dev` 中可以看到 `draft: true` 的文章。
- `pnpm build` 中不会生成 `draft: true` 的文章页面。

发布前先在本地开发服务器中检查文章排版，再执行生产构建确认 Frontmatter、图片和链接都能正常处理。

## About 页面

About 页面不是 `posts` collection，而是读取 `src/content/spec/about.md`。修改 About 内容时直接编辑该文件，不要把它放入 `src/content/posts/`。
