# 开发环境与常用命令

## 环境要求

| 工具 | 当前约定 |
| --- | --- |
| Node.js | `>=20`；GitHub Actions 当前使用 Node.js 22 和 23 验证 |
| pnpm | `>=9`；仓库的 `packageManager` 为 `pnpm@9.14.4` |
| Git | 用于获取代码和提交变更 |

`package.json` 没有声明 `engines` 字段，因此上表是项目文档和 CI 的运行约定，不是安装器强制执行的版本限制。为减少差异，本地开发建议使用 Node.js 22 和 pnpm 9.14.4。

## 初始化项目

在仓库根目录执行：

```bash
git clone <repository-url>
cd <repository-directory>
npm install --global pnpm@9.14.4
pnpm install
```

如果本机已经安装兼容版本的 pnpm，只需执行 `pnpm install`。CI 使用 `pnpm install --frozen-lockfile`，因此更新依赖后应一并提交 `pnpm-lock.yaml`。

## 本地开发

```bash
pnpm dev
```

开发服务器默认运行在 `http://localhost:4321`。修改 `src/` 或 `src/content/posts/` 后，Astro 会在开发服务器中重新加载页面。

### 内容管理界面

另开一个终端启动 Sveltia CMS：

```bash
pnpm cms
```

浏览器打开终端输出的地址，默认是 `http://127.0.0.1:4325`。选择当前 Git 仓库根目录后，即可在浏览器中管理文章及其图片；本地预览仍由 `pnpm dev` 提供。

CMS 依赖 Chromium 的 File System Access API，推荐使用 Chrome 或 Edge。它直接修改工作区文件，不会自动提交或推送 Git。端口冲突时可通过 `CMS_PORT` 环境变量指定其他端口。

预览生产构建：

```bash
pnpm build
pnpm preview
```

`pnpm preview` 需要先存在最新的 `dist/` 构建产物。

## 常用命令

所有命令都从仓库根目录执行。

| 命令 | 作用 | 是否修改文件 |
| --- | --- | --- |
| `pnpm dev` | 启动 Astro 开发服务器 | 否 |
| `pnpm install` | 安装依赖 | 可能更新依赖目录 |
| `pnpm new-post <slug> [标题]` | 创建 page bundle 格式的草稿文章 | 是 |
| `pnpm cms` | 启动 Sveltia CMS 本地管理界面 | 否 |
| `pnpm check` | 运行 `astro check` | 否 |
| `pnpm type-check` | 运行 TypeScript 声明检查 | 否 |
| `pnpm lint` | 使用 Biome 检查并自动修复 `src/` | 是 |
| `pnpm format` | 使用 Biome 格式化 `src/` | 是 |
| `pnpm build` | 构建站点并生成 Pagefind 搜索索引 | 生成 `dist/` |
| `pnpm preview` | 预览已有生产构建 | 否 |
| `pnpm astro ...` | 调用 Astro CLI | 取决于子命令 |

`pnpm lint` 和 `pnpm format` 都带有 `--write`，运行后应检查变更是否符合预期。需要只读 CI 检查时，使用工作流中的 `biome ci ./src`。

## 提交前检查

建议按以下顺序执行：

```bash
pnpm check
pnpm type-check
pnpm lint
pnpm format
pnpm build
```

格式化和 lint 可能修改源码；确认修改后再提交。仓库的 CI 还会在 Node.js 22 和 23 上执行 `pnpm astro check` 和 `pnpm astro build`，并单独执行 `biome ci ./src`。
