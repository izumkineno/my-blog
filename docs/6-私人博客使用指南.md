# 私人博客使用指南

本文说明如何把 Fuwari 作为个人博客使用。这里的“私人博客”指个人维护、个人发布的博客；项目本身是静态站点，不包含登录、后台管理或访问控制。

## 一、先理解项目的工作方式

文章、配置和图片都保存在仓库文件中：

- 文章位于 `src/content/posts/`。
- About 页面内容位于 `src/content/spec/about.md`。
- 站点名称、语言、导航、头像和个人资料位于 `src/config.ts`。
- `pnpm build` 生成静态站点和 Pagefind 搜索索引。
- `dist/` 是构建产物，不是内容源文件。

因此，日常使用方式是“本地编辑 Markdown，启动开发服务器预览，构建后发布静态文件”，不需要数据库或在线 CMS。

## 二、第一次配置个人博客

### 1. 安装并启动

在仓库根目录执行：

```bash
pnpm install
pnpm dev
```

浏览器打开 `http://localhost:4321`，确认模板可以正常运行。环境要求和完整命令见[开发环境与常用命令](./1-开发环境与常用命令.md)。

### 2. 修改站点身份

编辑 [`src/config.ts`](../src/config.ts) 中的配置：

- `siteConfig.title`：博客名称。
- `siteConfig.subtitle`：副标题或一句话介绍。
- `siteConfig.lang`：博客默认语言。
- `profileConfig.name`：作者名称或笔名。
- `profileConfig.bio`：个人简介。
- `profileConfig.avatar`：头像路径。
- `profileConfig.links`：社交账号或个人主页。
- `licenseConfig`：文章页显示的许可证信息。

配置中的 demo 文本、头像、Banner、社交链接和 GitHub 链接都应按个人情况替换或删除。

### 3. 修改导航和 About 页面

`navBarConfig.links` 控制顶部导航。可以保留 Home、Archive、About，也可以替换为个人主页等自定义链接。

About 页面内容不在文章集合中，直接编辑 [`src/content/spec/about.md`](../src/content/spec/about.md)。建议至少介绍：

- 你是谁，以及博客关注的主题。
- 文章更新频率或内容范围。
- 图片、代码和转载内容的版权说明。
- 联系方式或其他主页入口。

### 4. 设置正式站点地址

发布前修改 [`astro.config.mjs`](../astro.config.mjs) 中的 `site`：

```js
site: "https://your-domain.example/",
base: "/",
```

如果博客部署在域名的子路径下，再同步设置 `base`。这会影响文章链接、RSS、sitemap、robots.txt 和搜索索引。

## 三、日常写作流程

### 1. 创建文章

使用脚本创建文章：

```bash
pnpm new-post my-first-post
```

文章会生成到 `src/content/posts/my-first-post.md`。需要保存文章图片时，可以创建 page bundle：

```bash
pnpm new-post notes/my-first-post
```

这样文章会位于 `src/content/posts/notes/my-first-post.md`；也可以把目录改成 `my-first-post/`，并使用 `index.md` 作为文章入口。详细规则见[文章与内容开发](./3-文章与内容开发.md)。

### 2. 填写 Frontmatter

文章至少需要标题和发布日期：

```yaml
---
title: My First Blog Post
published: 2026-01-01
description: A short description for the post.
image: ./cover.jpg
tags: [Notes, Life]
category: Personal
draft: true
lang: zh_CN
---
```

建议每篇文章都填写 `description`、`tags` 和 `category`，便于首页摘要、归档筛选和搜索使用。文章语言与站点默认语言不同时填写 `lang`。

### 3. 本地预览

```bash
pnpm dev
```

重点检查：

- 标题、日期、摘要和封面是否正确。
- 文章目录是否符合预期。
- 图片、外部链接和代码块是否正常。
- 标签和分类是否能在 Archive 中筛选。
- 移动端和暗色模式下排版是否正常。

## 四、草稿、发布和撤回

### 草稿

新文章建议先设置：

```yaml
draft: true
```

开发环境会显示草稿，方便本地预览；生产构建会排除 `draft: true` 的文章。

### 发布

确认内容后改为：

```yaml
draft: false
```

然后执行：

```bash
pnpm build
pnpm preview
```

在本地预览生产构建，确认文章确实出现在列表、归档和搜索中，再把构建结果交给部署平台。

### 撤回文章

将已发布文章重新设置为 `draft: true` 后重新构建即可。已经被搜索引擎或读者缓存的页面不会立即从外部缓存中消失；需要根据部署平台的缓存策略处理。

## 五、图片和内容整理建议

- 文章专属图片放在文章所在目录，使用 `image: ./cover.jpg` 等相对路径。
- 多图文章使用独立目录，避免所有图片堆在同一个目录。
- 公共 favicon 或全站静态文件放在 `public/`。
- 由 Astro 处理的站点图片可以放在 `src/assets/`。
- 标签使用稳定、可复用的名称；分类用于更高层级的主题划分。
- 不要把密码、Token、私钥或其他敏感信息写入 Markdown、Frontmatter 或图片元数据。

图片路径和 Markdown 扩展见[文章与内容开发](./3-文章与内容开发.md)。

## 六、备份与维护

Git 仓库是博客的主要备份来源。至少应保留以下内容：

- `src/content/posts/` 中的文章和文章图片。
- `src/content/spec/about.md`。
- `src/config.ts` 和 `astro.config.mjs`。
- `src/assets/`、`public/` 中的个人资源。
- `package.json` 和 `pnpm-lock.yaml`。

`dist/`、`.astro/` 和 `node_modules/` 可以重新生成，不需要作为内容备份提交。每次发布前建议执行：

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm build
```

构建、CI 和发布检查见[构建检查与部署](./5-构建检查与部署.md)。

## 七、关于“私人”的边界

当前工程默认生成公开静态页面：

- `draft: true` 只是在生产构建时排除文章，不是访问权限控制。
- 只要文章被构建并部署，任何拿到 URL 的人都可能访问它。
- 将 Git 仓库设为 private 只能保护源代码，不会自动保护已经发布的网站。
- 真正需要登录、仅自己可见或按用户授权时，需要在部署平台增加访问控制，或使用带认证的服务；当前模板没有提供这部分能力。

因此，私人博客的安全边界应放在“源仓库权限、部署平台权限和内容发布检查”上，而不是依赖草稿字段隐藏敏感内容。

## 八、推荐的个人发布清单

1. 修改 `src/config.ts` 中的站点身份、作者信息和导航。
2. 修改 `src/content/spec/about.md`。
3. 修改 `astro.config.mjs` 中的 `site` 和必要的 `base`。
4. 用 `pnpm new-post` 创建文章，并先使用 `draft: true`。
5. 在 `pnpm dev` 中检查内容和响应式布局。
6. 发布前运行 `pnpm check` 和 `pnpm build`。
7. 用 `pnpm preview` 检查生产结果，再提交并部署。
8. 定期备份文章、图片和配置文件。
