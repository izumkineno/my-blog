# 站点配置与主题定制

主要配置集中在 [`src/config.ts`](../src/config.ts)。修改后重启开发服务器通常不是必需的，但涉及 Vite、Astro integration 或路径时建议重新启动并执行一次构建。

## 站点与主题

`siteConfig` 控制全局站点行为：

| 配置 | 作用 |
| --- | --- |
| `title` | 站点标题 |
| `subtitle` | 默认副标题和站点描述 |
| `lang` | 默认语言；可选 `en`、`zh_CN`、`zh_TW`、`ja`、`ko`、`es`、`th`、`vi`、`tr`、`id` |
| `themeColor.hue` | 主题色色相，范围为 0 到 360 |
| `themeColor.fixed` | 是否隐藏访客主题色选择器 |
| `banner.enable` | 是否启用 Banner |
| `banner.src` | Banner 图片路径 |
| `banner.position` | Banner 图片位置：`top`、`center` 或 `bottom` |
| `banner.credit` | 是否显示图片署名及其链接 |
| `toc.enable` | 是否显示文章目录 |
| `toc.depth` | 目录最大标题深度，支持 1、2、3 |
| `favicon` | 自定义 favicon 列表；为空时使用默认 favicon |

默认配置仍使用 Fuwari 的 demo 文本和资源。fork 或部署前至少应修改 `title`、`subtitle`、`lang`、`profileConfig`，并检查 Banner、favicon 和许可证内容。

## 导航、个人资料与许可证

- `navBarConfig.links` 可以使用 `LinkPreset.Home`、`LinkPreset.Archive`、`LinkPreset.About`，也可以传入自定义链接对象。
- 内部导航 URL 不要手动拼接 `base`；项目的 URL 工具会统一处理站点基础路径。
- 自定义链接设置 `external: true` 后会被当作外部链接，并在新标签页打开。
- `profileConfig` 控制头像、名称、简介和社交链接；社交链接的 `icon` 使用 Iconify 图标名称。
- `licenseConfig` 控制文章页面是否显示许可证、许可证名称和详情 URL。

配置类型定义在 [`src/types/config.ts`](../src/types/config.ts)，新增字段时应先同步类型，再修改使用它的组件。

## 图片与静态资源

配置文件中的图片路径遵循以下规则：

- 不以 `/` 开头的路径相对于 `src/`，例如 `assets/images/demo-banner.png`。
- 以 `/` 开头的路径相对于 `public/`，例如 `/favicon/favicon-light-32.png`。
- `public/` 中的文件会原样复制到构建结果；`src/assets/` 中的资源由 Astro 处理。

同一条路径规则也适用于文章封面，详细说明见[文章与内容开发](./3-文章与内容开发.md)。

## 站点 URL 与部署前配置

[`astro.config.mjs`](../astro.config.mjs) 中的三个字段直接影响部署：

```js
site: "https://your-domain.example/",
base: "/",
trailingSlash: "always",
```

- `site` 应改为实际域名，用于 sitemap、RSS 和 robots.txt 等绝对 URL。
- `base` 默认是 `/`；如果站点部署在子路径，需要设置为对应路径，例如 `/blog/`。
- 项目内部 URL 通过 `src/utils/url-utils.ts` 读取 Astro 的 `BASE_URL`，不要在组件中重复实现路径拼接。
- `trailingSlash: "always"` 表示生成带结尾斜杠的页面 URL，新增链接时保持一致。

## i18n 与样式

- 翻译键位于 `src/i18n/i18nKey.ts`，各语言文本位于 `src/i18n/languages/`。
- 新增语言时，需要同时更新 `src/types/config.ts` 的语言联合类型、语言文件和翻译加载逻辑。
- 全局样式主要位于 `src/styles/`；Markdown 内容样式位于 `src/styles/markdown.css`。
- UI 组件位于 `src/components/`，交互组件通常使用 Svelte，页面和布局使用 Astro。
- Tailwind 内容扫描范围在 `tailwind.config.cjs`；新增源码目录后要确认它仍被扫描。
