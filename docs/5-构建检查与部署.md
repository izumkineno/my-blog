# 构建、检查与部署

## 构建产物

项目使用 Astro 的静态构建模式。执行：

```bash
pnpm build
```

该命令实际执行 `astro build && pagefind --site dist`：

1. Astro 将页面、资源和 sitemap 等内容写入 `dist/`。
2. Pagefind 扫描 `dist/`，生成站内搜索索引。

`dist/` 是构建输出目录，已被 `.gitignore` 忽略，不应提交到仓库。

构建后可用以下命令启动本地预览：

```bash
pnpm preview
```

## 发布前检查

```bash
pnpm check
pnpm type-check
pnpm lint
pnpm format
pnpm build
```

`lint` 和 `format` 会写回 `src/`，运行后检查工作区差异。至少应确认：

- 文章 Frontmatter 能通过 content schema 校验。
- 文章封面和 Markdown 内图片存在。
- `site` 和 `base` 与最终域名及部署路径一致。
- 生产构建不包含 `draft: true` 文章。
- Pagefind 索引已经生成，搜索功能可用。

## GitHub Actions

仓库包含三类 GitHub Actions 工作流：

| 文件 | 检查或部署内容 |
| --- | --- |
| `.github/workflows/build.yml` | Node.js 22、23 矩阵；安装锁定依赖后运行 `pnpm astro check` 和 `pnpm astro build` |
| `.github/workflows/biome.yml` | 使用 Biome CI 检查 `src/`，不自动写回文件 |
| `.github/workflows/deploy.yml` | `main` 分支更新或手动触发时，执行完整的 `pnpm build`，上传 `dist/` 并部署到 GitHub Pages |

部署工作流使用锁定版本的 GitHub Actions、Node.js 22 和 pnpm 9.14.4，并授予 Pages 部署所需的 `pages: write` 与 `id-token: write` 权限。完整构建包含 Pagefind，因此发布产物同时包含站内搜索索引。

## GitHub Pages 自动部署

推送到 `main` 后，`.github/workflows/deploy.yml` 会构建并发布站点；也可以在 GitHub 的 **Actions** 页面手动运行该工作流。当前配置对应：

- 站点地址：`https://izumkineno.github.io/my-blog/`
- Astro `site`：`https://izumkineno.github.io`
- Astro `base`：`/my-blog`
- 发布目录：`dist/`

首次启用时，需要在仓库 **Settings → Pages → Build and deployment → Source** 中选择 **GitHub Actions**。此后每次 `main` 分支构建成功都会自动更新页面。

如果以后绑定自定义域名，需要同步修改 [`astro.config.mjs`](../astro.config.mjs) 中的 `site` 和 `base`，并按 GitHub Pages 要求配置域名；不能只修改 DNS。

## 部署后检查

部署完成后至少检查以下地址和行为：

- 首页和分页页面可以打开。
- 单篇文章、About、Archive 页面可以打开。
- RSS、sitemap 和 robots.txt 使用正确的域名和基础路径。
- 亮色/暗色切换、文章目录和搜索正常。
- 一篇已发布文章可在搜索结果中找到，草稿文章不会出现在生产站点。
